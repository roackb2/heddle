# Heddle v5.6.0

Heddle v5.6 is a hosting-readiness release. It adds an explicit access boundary
for the reference control-plane server, makes session leases safe across
multiple replicas, gives direct file tools canonical workspace containment,
bounds runtime subscription buffers, and publishes a conformance suite that
certifies third-party conversation-archive repositories.

The theme is truthfulness about boundaries: each capability states what it
actually enforces, and where the host remains responsible.

## Hosted control-plane access boundary

- **Hosts own authentication; Heddle owns scope intersection.** A product host
  authenticates each request and returns a typed principal plus an allow-listed
  workspace/session scope. Heddle intersects client-supplied IDs with that
  resolved scope across both tRPC and REST routes, so a caller cannot reach a
  workspace or session outside its granted scope.
- **Operation-level authorization is available.** Hosts can add per-operation
  checks after Heddle's static scope check, using the
  `HeddleControlPlaneOperation` and `HeddleControlPlaneOperationAuthorization`
  contracts.
- **Approval and cancellation are actor-aware.** Those routes write actor-aware
  audit events to the workspace operation log and can forward them to a host
  audit sink through `HeddleControlPlaneAuditEvent`.
- **Local mode is documented as single-operator.** Local mode intentionally
  authenticates no one and permits every local workspace. It is not a hosted or
  multi-tenant deployment mode, and `src/server/access/README.md` now says so
  directly.

The server access surface is exported from `@roackb2/heddle/advanced`:
`createHeddleServerApp`, `startHeddleControlPlaneServer`,
`HeddleServerAccessError`, and the related `HeddleServer*` types.

## Replica-safe session leases

- **Leases carry host identity.** A lease owner is now identified by a stable
  `hostId` plus a per-instance `ownerId`, so two replicas that happen to
  generate equal process-local owner IDs are no longer treated as the same
  lease holder.
- **Fencing tokens replace liveness guessing.** `ChatSessionLeaseClaim` carries
  a monotonic `fencingToken`, and lease conflict resolution no longer depends on
  a local `isProcessAlive(pid)` probe — a check that is meaningless when the
  previous holder ran on a different machine.

## Canonical workspace containment for direct file tools

- **Every coding-file operation resolves canonically before access.** Existing
  targets use their canonical `realpath`; new targets use the canonical nearest
  existing parent plus the missing suffix; moves validate both source and
  destination.
- **Approval sees the same path execution uses.** Approval and Auto policy
  receive the canonical target, so the path a human approves is the path the
  operation acts on. An in-workspace symlink can no longer redirect a
  coding-file operation outside the configured root.
- **The guarantee is stated honestly.** Canonical containment is defense in
  depth. It is not an operating-system sandbox, it does not cover shell command
  filesystem access, and it cannot eliminate filesystem time-of-check/
  time-of-use races. Hosts running untrusted workloads should still use mature
  OS isolation and least-privilege filesystem permissions.

## Bounded runtime subscriptions

- **Each subscription retains at most `maxBufferedEvents` payloads** (256 by
  default). Exceeding the bound fails the iterator with
  `RuntimeSubscriptionOverflowError`, releases queued payloads and source
  resources, and invokes an optional `onOverflow` hook for host metrics.
- **Overflow never silently drops events.** A stream does not pretend to
  complete. Sources with durable replay reconnect from their last consumed
  cursor (conversation runs use `afterSequence`); sources without durable replay
  should treat overflow as an invalidation signal and refetch before
  resubscribing.
- **Subscribers are independently bounded.** One stalled client can overflow and
  disconnect without slowing or corrupting another subscriber.

## Certified archive repositories

- **`ChatArchiveRepositoryConformance` is a published suite.** Adopters
  implementing a custom conversation-archive repository can run the same
  scenarios Heddle uses, including manifest-corruption handling, and get
  `ChatArchiveRepositoryConformanceError` on divergence.
- **The PostgreSQL/Drizzle persistence example is certified against it**, so the
  reference adapter and the contract cannot drift apart silently.

## Upgrade notes

- Install `@roackb2/heddle@5.6.0`. `@roackb2/heddle-remote@5.6.0` releases in
  lockstep and its ordered run protocol remains compatible.
- No persisted data migration is required.
- If you implement `ChatSessionLeaseRepository` or construct lease owners
  directly, add a stable `hostId` to each owner and stop passing
  `isProcessAlive` in lease conflict options. These types are internal to the
  conversation engine and are not exported from the package entrypoints, so
  most adopters are unaffected.
- If you host the reference control-plane server, decide explicitly between
  local single-operator mode and a hosted access control implementation. Local
  mode performs no authentication.
- If you consume runtime subscriptions directly, handle
  `RuntimeSubscriptionOverflowError` by refetching canonical state and
  resubscribing rather than treating it as normal completion.
