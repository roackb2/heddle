# Heddle v5.11.0

Heddle v5.11 introduces a small, independently installable SDK for product
backends that invoke a Heddle Execution Host. Adopters can now implement the
signed authority, MCP capability, and streaming client boundary without
importing the Heddle runtime or its infrastructure dependencies.

## Heddle Adopter SDK

- **`@roackb2/heddle-adopter` is a new public package.** It publishes the
  versioned Execution Host contracts, strict schemas, and TypeScript reference
  types used between an adopter backend and an Execution Host.
- **Backends can mint short-lived execution authority.** The ES256 authority
  service issues an execution assertion and, when configured, a separately
  scoped MCP capability while exposing only the corresponding public JWKS.
- **Product MCP servers can verify capabilities independently.** The verifier
  binds issuer, audience, adopter, server, supported tools, and expiry at the
  adopter edge instead of trusting model-controlled tool arguments.
- **A strict direct HTTP/SSE client is included.** The client validates the v1
  event sequence, withholds terminal success until clean EOF, bounds response
  buffering, propagates cancellation, and never retries an ambiguous run.

## Boundary and portability

- The package has no dependency on Heddle, AWS SDKs, or the MCP server SDK.
- Product authentication, tenant mapping, data access, tool implementation,
  key storage, and durable result projection remain adopter responsibilities.
- AgentCore ingress, SigV4, runtime isolation, the Heddle loop, and deployment
  operations remain Execution Host responsibilities.
- The TypeScript package is the first reference implementation of the v1
  network contract. Other languages can implement the same JSON, JWT, JWKS,
  MCP, and SSE boundary without porting Heddle itself.

## Upgrade notes

- Existing `@roackb2/heddle` and `@roackb2/heddle-remote` users do not need to
  change code; their runtime APIs are unchanged in this release.
- Install `@roackb2/heddle-adopter@5.11.0` only in adopter backend services that
  need to call an Execution Host or verify its MCP capabilities.
- The included direct client targets local development or explicitly reviewed
  HTTPS endpoints. A managed AgentCore/SigV4 transport remains a separate host
  integration concern.
