# Heddle v5.13.0

Heddle v5.13 makes the hosted-agent boundary substantially easier to adopt and
adds a durable, low-volume heartbeat deployment path. A product backend can now
reuse Heddle's Node control-plane machinery, expose narrowly authorized MCP
tools, and run targeted heartbeat work against an optional PostgreSQL authority
without reimplementing the generic protocol and lifecycle layers.

## Execution Host adopters

- **Node backends get an assembled adopter edge.**
  `@roackb2/heddle-adopter/node` now provides execution-authority key loading and
  generation, direct-host credentials, JWKS and conversation HTTP/SSE handling,
  bounded request parsing, cancellation, and clean shutdown.
- **Conversation orchestration is reusable.**
  `HostedConversationTurnService` owns the generic issue-authority, invoke-host,
  stream, and terminal-result flow while leaving authentication, product scope,
  prompts, and result projection to the adopter.
- **Product capabilities remain product-owned without MCP boilerplate.**
  `@roackb2/heddle-adopter/mcp/node` supplies a stateless Streamable HTTP MCP
  edge plus declarative JSON tools. Adopters still define every tool's name,
  schema, authorization, and domain operation.
- **The private Execution Host is not presented as a public managed service.**
  These APIs are public integration machinery and a language-neutral reference
  implementation for teams building or evaluating their own hosted Heddle
  boundary.

## Targeted heartbeat execution

- **A public targeted worker/dispatcher host now owns the low-volume execution
  loop.** It combines durable run requests, polling fallback, bounded
  concurrency, cancellation, delayed redelivery, recovery, and clean shutdown
  without requiring adopters to reproduce scheduler policy.
- **The host stays storage-neutral.** Applications provide the public task
  authority and invocation target, so product identity and side effects remain
  outside Heddle's infrastructure layer.

## Optional PostgreSQL authority

- **`@roackb2/heddle-postgres` is a new optional package.** It implements the
  public heartbeat task store and administration contracts with Drizzle and an
  adopter-supplied PostgreSQL database connection.
- **Claims and administration are transactional.** Row locking, due-task
  claims, execution fencing, fixed leases, expired-lease recovery, checkpoints,
  run history, reconciliation, and operator controls share the same PostgreSQL
  authority.
- **Infrastructure ownership stays explicit.** The package opens no database,
  starts no worker, performs no migration automatically, and owns no tenant
  authentication. Apply the shipped baseline migration deliberately and derive
  each namespace from trusted deployment or application authority.

## Upgrade notes

- Install the lockstep `5.13.0` Heddle packages used by your application.
- `@roackb2/heddle-postgres` is published for the first time in this release and
  requires `@roackb2/heddle >=5.13.0 <6` plus a compatible Drizzle PostgreSQL
  database.
- The PostgreSQL execution lease is intentionally fixed in this first release;
  configure it longer than the maximum bounded task attempt. Lease renewal is
  not yet part of the public contract.
- Existing conversation, remote-client, heartbeat scheduler, and adopter APIs
  do not require code changes.
